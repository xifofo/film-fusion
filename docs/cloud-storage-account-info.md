# 云存储 115 账户资料

云存储管理双击 `115open` 存储的「账户信息」单元格读取或更新资料，选中后按 Enter 也可触发；列头问号提供操作说明。该操作按需执行，不在列表加载、翻页或自动刷新令牌时调用；使用存储已有 OpenAPI 访问令牌，不读取 Cookie，不进入 SDK 的自动令牌刷新链。令牌失效时保留原资料并提示检查授权。

首次添加不再填写存储名称，只选择应用并扫码。`POST /api/auth/115/qrcode` 的 `name` 为可选旧客户端字段，不再用于命名；完成授权时复用 SDK `UserInfo` 获取账号 UID 的同一次响应，将完整已知资料与授权凭据一同保存，不额外调用资料接口。新建名称为去除首尾空白的 `user_name` 加「的网盘」，昵称为空时回退为「115 UID的网盘」。用户随后可双击存储名称修改；重新授权更新资料快照但保留自定义名称。资料获取失败或 UID 无效时不创建存储，额外配置不是有效 JSON 对象时拒绝覆盖。

## 接口与保存

`POST /api/cloud-storage/:id/account-info` 沿用云存储的认证与用户归属范围；其他用户的记录返回 404，不支持的存储类型或未授权记录返回 400。服务端以 `GET https://proapi.115.com/open/user/info` 读取资料，调用最多 30 秒、响应最多 1 MiB，禁止跟随重定向。

成功后合并 `config` 顶层的 `115_account_info` 字段：

```json
{
  "115_account_info": {
    "fetched_at": "2026-11-06T08:00:00Z",
    "data": {
      "user_id": 12345,
      "user_name": "账户昵称",
      "user_face_s": "https://example.com/avatar.png",
      "user_face_m": "https://example.com/avatar.png",
      "user_face_l": "https://example.com/avatar.png",
      "vip_info": { "level_name": "会员", "expire": 1900000000 },
      "rt_space_info": {
        "all_total": { "size": 1099511627776, "size_format": "1 TB" },
        "all_use": { "size": 1024, "size_format": "1 KB" },
        "all_remain": { "size": 1099511626752, "size_format": "1 TB" }
      }
    }
  }
}
```

资料采用当前 SDK 的 `UserInfoResp` 已知字段；不会把访问令牌、刷新令牌或 Cookie 加入资料快照。原配置的其他字段保留，空配置作为对象处理，非对象或无效 JSON 返回 400。额外配置由系统维护，前端不展示原始 JSON 编辑入口，普通更新接口不接受 `config` 字段覆盖快照；账户资料和保活详情以只读摘要展示。若 `provider_uid` 为空则回填读取到的账号 ID；非空且不一致返回 409，防止资料串号。

保存只写 `config`、`provider_uid` 与 `updated_at`，比较调用前的配置、访问令牌与账号 ID；获取期间发生变化或记录被删除时返回 409，不覆盖并发修改。成功响应仅含 `id`、`config`、`provider_uid`、`updated_at`，前端合并这些字段，不用旧整行覆盖新凭据。

## 代码职责

前端 `CloudStoragePage` 组合表格、筛选和互斥弹窗；`useCloudStorages` 管理账号隔离的读取、缓存合并、删除和排序逆操作；`StorageToolbar` 统一工具栏与右键菜单；`StorageCookieRenewal` 和 `StorageEditor` 各自拥有草稿及取消信号；`storageAuth` 只负责授权请求。编辑白名单与可排序时间字段由领域请求模块统一维护，弹窗关闭后不保留旧账号的请求和设备草稿。

后端 `cloud_storage.go` 负责读取、归属校验与删除，`cloud_storage_write.go` 使用带指针的字段白名单执行部分更新，显式 `false`、零值与空字符串不会丢失，未提交的令牌不回写。`auth_115.go` 统一授权会话的用户和有效期检查，二维码状态直接调用 SDK；`auth_115_account.go` 完成凭据交换和资料保存。排序、删除引用与账户资料的服务各自保留原事务和并发校验。

旧 `POST /api/cloud-storage/:id/refresh` 和 `POST /api/cloud-storage/:id/test` 尚未实现真实操作，现在保留路由并返回 501，避免伪造成功或修改最后刷新时间。自动令牌刷新服务与 Cookie 续期接口不受影响。

## 展示与验证

只有 `115open` 存储展示资料：一个自定义多行单元格集中显示头像、昵称、UID、会员类型、会员到期日与已用／总容量，并提供容量占用条；无有效字节容量时不绘制进度条。可见时最小行高为 96 像素，隐藏该列可恢复紧凑行高。默认账户信息为首列，存储名称位于创建时间之前，单独的网盘账号 UID 列默认隐藏；已有个人列顺序继续保留，可恢复默认布局采用新顺序。完整资料仍通过列文本参与复制、导出和读屏。详情补充头像、会员期限、剩余空间及获取时间；未获取或快照账号与当前绑定不一致时，单元格标题显示「双击获取账户信息」，其他存储类型留空。资料是最近一次授权或手动获取的快照，不代表实时余额或会员状态。头像只接受 HTTPS URL。

服务层及 HTTP 测试使用临时 SQLite 和内存 HTTP 响应，覆盖配置合并、数字精度、凭据保留、跨用户访问、无效 ID／配置、上游失败、账号不一致、取消及并发变更；授权映射测试验证自动命名、无昵称回退及重新授权保留名称，不访问真实 115。真实验收需先部署后端，再添加新账号扫码，确认自动名称与资料保存后刷新仍保留；修改名称并重新授权应保留自定义名称。双击账户信息可再次更新，失败时原快照应保留。

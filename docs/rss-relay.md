# RSS 中转

RSS 中转是独立模块，在侧栏「RSS 中转」管理原始 RSS 地址、抓取间隔和缓存。它不需要创建自动化，也不属于任何自动化。

## 接入 FilmFusion 和 MP2

1. 打开侧栏「RSS 中转」，点击「添加 RSS 中转」，填写名称和原始 RSS 地址。
2. 原站限制两分钟一次时，保留默认最小抓取间隔 **180 秒**，启用并保存。
3. 复制该行的中转链接，分别填入 FilmFusion RSS 自动化和 MP2 的 RSS 地址。两个系统都停止直接轮询原始地址。
4. MP2 在容器或其他机器中时，链接的域名和端口必须是其可访问的 FilmFusion 地址；不能照搬仅浏览器本机可用的 localhost。

启用后中转服务独立定时抓取，调度每 15 秒检查到期项；实际抓取还会等待网络请求完成。手动刷新和客户端访问也可以触发到期抓取，均遵守相同冷却时间。刷新状态仅查询本地状态。

## 独立生命周期

- 停用或删除自动化不会影响中转的调度、缓存和链接；无需任何自动化，中转也能给 MP2 使用。
- 停用中转后停止定时抓取和链接访问（HTTP 404），保留缓存；重新启用继续使用原链接。已经发出的上游请求可能完成。显式手动刷新仍受冷却限制。
- 删除中转后链接失效，不删除任何自动化。使用方需要更换订阅地址。保留原始 URL 的冷却记录，避免删除后重建绕过限流。
- 重置链接或修改原始 RSS 地址后生成新凭证，旧链接立即失效，需要同步更新消费端。

## 缓存和限流

- 中转使用独立的 `rss_relays` 表和 `RSSService`，与自动化分别启动和停止。共享抓取层的缓存和冷却记录持久化在 `rss_feed_caches`。
- 默认间隔 180 秒，可配置 120～86400 秒。同一完整原始 URL 共用缓存和间隔；若添加重复地址，最新保存的间隔对这些中转统一生效。自动化直接读取同一原始 URL 时也复用此抓取层。
- 每次请求前原子预留抓取资格，避免并发调用和服务重启绕过冷却。请求超时为 30 秒，抓取占用有到期时间。
- 原始 RSS / Atom XML 原样存储并返回，保留 GUID、命名空间、下载链接及扩展字段；映射和条目去重由消费方独立执行。
- HTTP 304 保留内容并更新成功时间；429、超时、无效 XML、服务器错误不覆盖成功缓存，并遵守 `Retry-After`（秒数或 HTTP 日期）。
- 带 `If-None-Match` / `If-Modified-Since` 的条件请求遇到 HTTP 5xx 时，按完整 RSS URL 持久化停用条件请求，下次允许抓取时改用普通请求；不会立即重试。后续成功响应即使再次声明 ETag / Last-Modified，也不会重新启用条件请求，容器重启后同样保留。其他 RSS 地址继续正常使用条件请求；抓取间隔、共享缓存和条目去重不变。普通请求遇到 5xx 不会触发此兼容处理。
- 有缓存时，上游失败仍返回最后成功的 XML，界面展示异常及最近成功时间；无缓存且冷却中时返回 HTTP 503 和可用的 `Retry-After`，不伪造空 RSS。
- 不自动跟随 HTTP 重定向，以免产生未受限的额外请求；遇到重定向请配置最终 RSS 地址。
- 按完整 URL 隔离缓存，保留查询参数中的账号凭证和筛选条件。若原站按账号或 IP 将多个不同 RSS URL 共用一个额度，此功能不合并这些 URL；可以统一使用一个原始地址，在消费端筛选。

## 接口

管理员接口均独立于 `/api/automations`：

- `GET /api/rss-relays`：列表及缓存状态。
- `POST /api/rss-relays`：创建；请求体为 `name`、`feed_url`、`enabled`、`min_interval_seconds`。
- `GET /api/rss-relays/:id`：查看。
- `PUT /api/rss-relays/:id`：编辑，与创建使用相同请求体。
- `PATCH /api/rss-relays/:id/enabled`：启停，请求体 `{ "enabled": true }`。
- `POST /api/rss-relays/:id/refresh`：按冷却规则刷新缓存。
- `POST /api/rss-relays/:id/token`：重置链接。
- `DELETE /api/rss-relays/:id`：删除中转。
- 消费端 `GET /api/rss-relay/:id/:token`：返回原始 XML，无需管理员 JWT。响应头 `X-RSS-Cache` 为 `MISS`、`HIT` 或 `STALE`，并附带 `X-RSS-Last-Success`、`X-RSS-Next-Fetch`。

包含 token 的中转链接等同于读取此私有 RSS 的凭证，仅提供给自己的系统。缓存内容可能包含原站下载凭证，应与数据库备份一起妥善保管。

# Emby 批量查入库

入口：Film Fusion → Emby → 批量查入库（`/emby/library-check`）。使用当前配置的 Emby 地址和 API Key，只查询电影和剧集条目。

## 使用

1. 每行粘贴一个名称，每次最多 200 个非空行。
2. 点击“开始查询”。系统去掉首尾空白、成对引号及常见视频、字幕、STRM、种子后缀，并合并重复名称。
3. 按状态筛选结果；“复制未找到的名称”只复制确认未找到的清理后名称，不包括疑似匹配和查询失败。
4. 已入库和疑似匹配的候选提供“打开 Emby”链接，直接定位到该服务器的条目详情页。
5. 未找到的结果提供“创建文件夹并移入”入口：选择已配置的 115 账号、源目录和具体文件，再独立选择目标父目录，并编辑文件夹名称。

例如 `星际穿越.mkv` 和 `星际穿越.MP4` 合并为 `星际穿越`。未知后缀和片名本身的点号保留。此功能只清理文件后缀，不解析发布组、分辨率、季集编号等资源命名信息。

| 状态 | 含义 |
| --- | --- |
| 已入库 | Emby 条目的名称或原始名称匹配；比较时忽略大小写、空白及标点，并统一 Unicode 兼容字符。 |
| 疑似匹配 | Emby 搜索返回相似候选，但没有名称匹配；候选过多、未搜索完时也保持待确认。 |
| 未找到 | 在本次 Emby 搜索中没有有效电影或剧集候选。别名、不同译名等仍可能需要手动搜索核对。 |
| 查询失败 | 连接、超时、响应格式或分页异常，无法判断入库状态。 |

结果显示原始名称、清理后名称，以及候选名称、类型、年份和路径。电影或剧集名称匹配不代表具体分辨率、版本或全部剧集齐全。修改输入后旧结果会被标记，并暂停复制功能，直到重新查询。

## 创建文件夹并移入

源目录和目标父目录分别选择，目标位置不固定为源目录。新文件夹名称默认使用清理后的名称，也可修改；最终提交前展示选中的源文件和完整目标路径。移动在同一个 115 账号内进行，不执行跨账号转存。

执行时重新核对源文件 ID、名称和父目录，再在目标父目录中创建或复用指定文件夹。检测到目标同名条目时停止移动。若文件夹已创建而移动失败，保留已创建的文件夹信息及表单，便于安全重试；如果同一文件已经位于指定目标内，则返回已移动。

移动完成仅表示 115 文件位置已更新，不会将该行标记为 Emby 已入库，也不会自动刷新 Emby 媒体库。

### 自动生成本地 STRM

文件移动确认成功后，按当前用户、同一 115 账号下的“云路径映射管理”配置匹配实际目标路径。目标路径由 115 返回的目录层级校验得到，不使用前端传入的路径写本地文件。

- `clouddrive2`：匹配时去掉云盘源路径的第一层。例如 `/115网盘/电影` 按 `/电影` 匹配实际 115 目录。
- `moviepilot2`：直接使用云盘源路径匹配。
- 按目录边界匹配，`/电影` 不会命中 `/电影备份`；优先使用最具体的映射，相同优先级的多个映射会提示冲突。

生成时保留既有 STRM 路径规则：CloudDrive2 会补回第一层挂载名。例如源路径 `/115网盘/电影`、本地路径 `/strm`，移动后的文件 `/电影/片名/片名.mkv` 会生成 `/strm/115网盘/电影/片名/片名.strm`。STRM 内容沿用该映射的内容前缀和 URI 编码设置，包含完整的 `/115网盘/电影/片名/片名.mkv` 路径。

未匹配映射或不符合 STRM 过滤规则时跳过；下载类文件不会在此流程自动下载。已存在且内容一致的 STRM 可复用，内容冲突或写入失败会单独显示原因。此时云盘移动仍保持成功，可点击“重试生成 STRM”；服务端重新验证文件位于目标目录后重试本地生成，不重复创建目录或移动文件。

## API

`POST /api/emby-library-check`，需要 Film Fusion 管理员登录，或具有 `emby-library` 模块授权的 API Token。

```json
{"names":["星际穿越.mkv","漫长的季节.strm"]}
```

标准响应的 `data` 包含 `results`、`total` 和 `duplicates_removed`。每项结果包含 `original_name`、`name`、`status`、`matches`；失败时包含 `error`，搜索截断时包含 `truncated`。候选的可选 `emby_url` 使用查询时的 Emby 地址生成，不附带 API Key。

输入体最大 256 KiB，单行最多 1024 字节。每批最多并发查询 4 个名称，批次最长 120 秒，每个名称最长 10 秒。每个名称最多读取 500 个候选、展示 20 个匹配；虚拟条目和占位条目不计为入库。

115 文件操作使用 `cloud-storage` 模块权限，并校验账号归属：

- `GET /api/cloud-storage/:id/files`：使用 `access_method`、`cid`、`offset`、`limit` 分页浏览文件。
- `POST /api/cloud-storage/:id/folder-move`：提供 `access_method`、`source_parent_id`、`file_id`、`file_name`、`target_parent_id` 和 `folder_name`。部分失败后可携带已返回的 `folder_id` 重试；服务端仍核对目标目录身份。

移动成功的结果包含 `strm` 状态：`created`、`skipped` 或 `failed`，以及 `message`，匹配时还包含 `cloud_path_id` 和可用的 `local_path`。STRM 失败不会将已成功的移动改成失败。

## 验证边界

自动化测试和本地浏览器流程使用隔离的模拟 Emby / 115。Emby 查询只读；用户执行“创建文件夹并移入”才会创建文件夹或移动 115 文件。真实 Emby 的搜索结果仍取决于服务端元数据和版本。

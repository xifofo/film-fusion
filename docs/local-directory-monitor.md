# 本地 / NAS 目录监控

在「自动化中心 → 新建自动化 → 本地 / NAS 目录」创建监控。目录填写 **FilmFusion 后端进程可见的绝对路径**；Docker 部署填写容器内挂载路径。每个监控绑定一条可编辑流程，可以设置条件判断、通知、HTTP 请求、标题识别等动作，并通过已有运行历史查看执行结果、重试失败步骤。

本地事件不含 115 文件 ID，不能直接交给要求 115 文件批次的文件识别或整理节点。需要调用本地整理服务时，可在流程中配置该服务的 HTTP 接口。默认流程发送通知；保存时可设置是否立即启用，停用期间不会进行后台监控。

## 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 递归子目录 | 界面默认开启 | 持续发现已存在和后来新增的子目录 |
| 模式 | 自动 | 可选实时监听加补扫，或仅轮询；不支持的系统自动退回轮询 |
| 事件 | 新增 | 可选新增、修改；移动进入视为新增，不提供可靠的移动前路径或删除动作 |
| 对象 | 文件 | 可选文件、目录、两者 |
| 首次扫描 | 仅建立基线 | 也可选择处理已有内容；两者均需稳定观测后才能执行动作 |
| 补扫间隔 | 300 秒 | 30–86400 秒；NAS 远端写入的发现延迟主要由补扫决定 |
| 稳定等待 | 30 秒 | 1–86400 秒，至少两次观测一致，变化后重新计时 |
| 原生目录监听上限 | 1024 | 每源 1–8192；所有源共享 8192 个原生监听硬上限 |
| 扫描批次 | 128 | 16–512 个目录项；限制每次目录读取和数据库分页的对象数 |
| 每段扫描时间 | 2000 毫秒 | 100–10000 毫秒；在读取、复核、汇总、派发等阶段的批次边界让出执行机会 |
| 每段对象上限 | 4096 | 128–65536；与时间预算共同限制单次工作量 |
| 待处理运行上限 | 1000 | 1–100000；达到上限暂缓创建新运行，稳定候选保留在数据库中 |
| 完成任务历史保留 | 30 天 / 10000 条 | 按天数或数量分批清理最旧的可清理历史；活跃任务和仍被引用的记录受保护 |
| 消失路径索引保留 | 7 天 | 完整扫描确认消失后才计时，过期后分批删除索引；不删除磁盘上的文件 |
| 扩展名 | 不限 | 例如 `mkv, mp4, strm`，大小写不敏感；不限制递归发现目录 |
| 排除规则 | 空 | 对文件名或相对路径做 glob 匹配，例如 `*.part`、`*.tmp`、`@eaDir`；匹配目录后跳过整棵子树，`**` 不表示任意层级 |

修改路径、递归范围、筛选条件、事件类型或首次扫描策略会标记基线失效，由后续分段扫描重建，不在保存配置时同步删除整棵树的索引。修改扫描频率、稳定等待或资源上限保留已观察的内容与执行历史。停用释放原生监听，重新启用补扫；扫描正在进行时，修改操作返回忙碌状态，完成后可重试。

对于几十万个目录、百万级文件，界面提供“大目录预设”：仅定期扫描、补扫间隔 900 秒、稳定等待 60 秒，保留上述分段和积压限制。预设不改变目录、事件和筛选规则。补扫间隔是完整扫描之间的调度间隔，不是全树扫描必须完成的期限，也不构成发现延迟保证。

## 运行与资源控制

```text
fsnotify 事件 ─→ 有界变化目录集合 ─→ 优先检查变化目录 ─┐
                                                    ├→ SQLite 快照 / 稳定候选
定时补扫 / 手动扫描 ─→ 持久断点 ─→ 分段遍历与复核 ──┘             │
                                                                ↓ 检查积压上限
                                                  自动化事件 → 运行 / 节点任务
                                                                ↓
                                                      有限 worker 执行配置动作
```

- 文件树、待扫描目录、候选状态保存在 SQLite；不将全量目录树或所有事件放入内存。
- 稳定候选查询使用候选专用的部分索引，并在 SQLite 上明确指定该索引，避免优化器为“没有待处理项”的查询反复扫描百万条快照；回归测试核对实际查询计划。
- 监听回调合并变化目录并发送容量 1 的唤醒信号；变化集合有全局上限，溢出后要求完整补扫。变化目录优先检查，完整扫描也保留执行机会。
- 原生监听目录数、运行时监控源数和扫描批次有明确上限；超过原生监听额度的目录继续通过轮询发现。扫描器最多跟踪 64 个源的实时状态，额外源仍定时扫描。全局最多保留 4096 个变化目录、64 个目录读取句柄；读取句柄用满时等待其它扫描释放，必要时回收闲置超过 5 分钟的句柄。
- 本地目录扫描内核串行工作，手动扫描也遵守同一并发限制。每段结束后释放扫描机会，调度器轮转监控源；尚未完成的扫描及时续接，等待稳定或积压时退避。目录读取分批完成，避免对单个大目录一次读取所有条目。
- 遍历、复核、目录汇总、缺失确认及派发都有持久阶段和断点。暂停一段不能当作整轮成功，也不能将尚未访问的对象误判为消失。重启或闲置句柄回收后恢复已完成的目录进度，当前未读完的目录重新枚举；频繁强制重启可能导致单个超宽目录反复重读。
- 首次基线完成后，稳定文件可以在后续完整补扫尚未结束时分段进入流程。目录动作需等对应子树复核及汇总完成。持续变化的对象继续等待稳定，其他已稳定对象可以推进。
- 正在读取的目录收到变化时，保存一次合并复扫请求，读到结尾后再检查；复扫期间仍有变化则交给后续完整补扫。候选按固定 ID 上界轮转，持续新增的高 ID 候选不会无限推迟旧候选。补扫仍受调度间隔影响；单个目录若无限追加且一直读不到结尾，不能承诺它及其子目录在有限时间内全部完成。
- 时间预算在批次边界检查，无法中断操作系统中已经阻塞的 NAS 读目录或文件属性调用；不应把 2000 毫秒解读为每次请求的硬超时。
- 动作复用现有持久化自动化队列；事件与待执行任务在同一事务落库，重启继续处理。外部 HTTP / 通知仍具有通常的重试语义，接收方应使用事件标识实现幂等，不能承诺外部副作用恰好执行一次。
- **资源上限是对象数和并发边界，不是整个 Go 进程的精确 MiB 配额**。实际 RSS 包括数据库缓存、Go 堆、路径长度和其它服务，须按实际目录规模测量。
- 索引仍需与可观察路径数量成比例的磁盘空间。任务历史清理不会移除活跃或受引用保护的记录，不能代替磁盘空间监控。SQLite 删除记录通常释放可复用页，不保证数据库文件立即缩小；扫描器不执行阻塞式全库压缩。

## 可观察性和边界

管理界面显示最近分段的目录 / 对象数、当前阶段、待扫目录、等待稳定数量、待处理运行、积压状态、实际原生监听数和最近完整扫描时间；执行历史沿用自动化中心。最近一段耗时和数量不能当作全树扫描的总耗时和总数量。

NFS / SMB 远端变动不能依赖本机文件事件，所以自动模式仍强制周期补扫。macOS / BSD 的 kqueue 后端可能为目录内文件隐式分配描述符，本实现使用轮询来保持监听资源边界。参考 [fsnotify 官方 FAQ 与平台说明](https://github.com/fsnotify/fsnotify#faq)。

目录不可访问、权限错误或扫描中断时不将其当作空目录，不产生删除动作；恢复后补扫。不会跟随符号链接。基线以第一次成功扫描的可观察状态为准；监听不能保证记录两次扫描之间短暂创建又删除的每个对象。稳定等待通过元数据及子树变化判断，不等同于下载器确认文件已经关闭；长时间暂停写入的任务可能先达到静默窗口，应配合临时文件排除规则或下载器完成后的原子移入。

本地触发字段可在流程中通过 `$item.*` 引用：`source`、`event_id`（稳定事件标识，可用于 HTTP 接收方去重）、`event_type`、`path`、`relative_path`、`root_path`、`name`、`title`、`is_directory`、`size`、`modified_at`。文本模板使用 `{{item.path}}` 等形式。HTTP 请求私网目标沿用现有显式允许私网选项。

本功能本地验证使用临时目录、隔离 SQLite 和 HTTP 模拟接收方；不需要访问实际 NAS、115 或通知账号。部署后的挂载可见性、权限、网络文件系统延迟和大规模内存占用需在实际环境验收。

## 验证记录（2026-10-22）

- Linux 无网络隔离容器中，35 项目录监控核心测试通过 `-race`，包括真实原生监听、监听失效恢复、索引迁移及 5 类实际候选查询的执行计划；无跳过。服务层本地监控、历史清理、配置更新和调度相关 race 测试通过。
- 前端相关 36 项测试、TypeScript 检查及生产构建通过。UI 测试的首次并行执行有 4 项触及默认 5 秒时限，单 worker、每用例 20 秒时限下全部通过。
- 规模测试使用 Apple M4 Pro、本机 APFS SSD、200200 个子目录和 100 万个零字节文件，按文件事件模式实际调用监控内核和磁盘 SQLite（WAL / FULL，单连接）。内存为扫描阶段每 100 毫秒及每段结束时采样的测试进程 RSS；迁移期间未采样 RSS，不包含整套应用、Linux 监听的内核内存，也不能替代 NAS 实测或长期稳定性测试。目录动作的子树复核及汇总耗时需另行测量。

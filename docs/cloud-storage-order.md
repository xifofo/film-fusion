# 云存储拖拽排序

`PUT /api/cloud-storage/order` 沿用云存储认证与当前用户范围。

请求必须包含当前用户完整、有序的 `expected: [{ id, sort_order }]` 快照，以及由相同 ID 组成的目标 `order: [id, ...]`。筛选结果或单页记录不能代替完整集合。

服务端在同一事务中比较现有列表、顺序和排序值，将目标顺序规范为从 1 开始的整数。增删记录、改序或修改排序值造成快照不匹配时返回 409；参数错误返回 400。任意一条写入失败时整组回滚。响应的 `data.items` 只包含 `id`、`sort_order`、`updated_at`，不包含授权凭据。

列表统一按 `sort_order ASC, created_at DESC, id DESC` 返回；最后一项用于稳定处理相同时间的记录。排序快照不依赖令牌刷新的更新时间。此接口不需要数据库迁移，前后端需要一起更新。

V2 使用表格行号旁的拖拽手柄，按完整集合计算筛选及分页中的落点。按日期等字段排序时暂停拖拽；清除字段排序后恢复。保存成功才更新界面，撤销和重做同样发送条件更新；服务器顺序变化后拒绝覆盖并刷新数据。

本地 SQLite 测试覆盖完整保存与逆操作、重复/缺失 ID、跨用户记录、排序冲突、增删冲突、事务回滚、并发写入、HTTP 鉴权、输入边界和凭据脱敏。隔离的浏览器环境使用 25 条临时记录及真实列表、排序处理器，已验证鼠标拖拽、撤销、重做、刷新持久化和筛选下保存完整顺序；此环境的登录为测试桩，不代表真实账号或 115 服务验收。真实账号写入需要两个以上存储及更新后的后端。

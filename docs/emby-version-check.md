# 本地多版本检查与文件删除

入口：Emby → 本地多版本检查（`/emby/version-check`）。后端按当前账号启用的媒体目录映射扫描本地路径，以电影或单集识别重复项；页面再按文件的完整父目录汇总。同名但不同路径的文件夹分别展示，跨目录重复保留关联目录。

## 查看和删除

1. 完成扫描后点击文件夹，查看该目录内涉及重复版本的文件。
2. 点击文件名查看完整路径、季集、版本特征、评分、大小和修改时间。这些信息来自扫描快照。
3. 勾选需要删除的文件，点击“删除本地文件”；文件详情也提供同一删除入口。单次最多 200 个文件，翻页会清空选区。
4. 确认框列出所有待删除文件的完整路径，并明确提示永久删除。非 STRM 文件另外提示会删除实体媒体文件。
5. “删除后请求 Emby 扫描媒体库”默认选中，可取消。确认后逐项显示已删除、已不存在或失败，以及独立的 Emby 扫描请求结果。

删除只执行所选路径的文件删除，不递归删除文件夹，也不连带删除 NFO、字幕、封面等文件。不调用云盘删除接口；STRM 指向的原片不会因删除该 STRM 而被删除。实体媒体位于挂载文件系统时，删除行为由该挂载实现决定。自动生成任务后续仍可能重新生成 STRM，此操作不会新增同步黑名单。

处理成功或确认文件已不存在后，当前扫描快照移除对应文件并重算重复项；只剩一个版本的媒体不再列为重复。其他文件是否新增、修改或消失仍需重新扫描。部分失败不会回滚已经完成的删除，失败项及原因保留在结果报告中。

## Emby 更新

删除成功后可向配置的 Emby 发出一次 `POST /Library/Refresh`，请求全库扫描。Emby 必须能访问同一套媒体文件；FilmFusion 与 Emby 的容器内路径名可以不同，但必须指向相同文件。

“已请求扫描”仅表示 Emby 接受请求，不表示扫描完成或所有客户端已更新。调用失败或超时单独提示，不把已完成的文件删除报成失败，也不自动重发未知请求。可在 Emby 管理界面检查任务或手动扫描。启用实时监控且文件系统支持时，Emby 也可能自行检测删除。

参考：[Emby 全库扫描 API](https://dev.emby.media/reference/RestAPI/LibraryService/postLibraryRefresh.html)、[媒体库实时监控](https://emby.media/support/articles/Library-Setup.html#enable-real-time-monitoring)。

## 删除接口

`POST /api/emby-version-check/files/delete`，管理员 JWT 或具有 `emby-version-check` 模块授权的 API Token。

```json
{
  "job_id": "当前扫描任务 ID",
  "files": [{"cloud_path_id": 7, "path": "/media/Movie/Movie.1080p.strm"}],
  "refresh_emby": true
}
```

请求体上限 256 KiB，文件数 1–200。路径和映射 ID 必须同时命中当前账号最近一次已完成扫描的重复项；旧任务、不属于扫描的路径、重复选择及正在执行的扫描/删除会被拒绝。执行前重新核对目录归属、启用状态和根路径，使用受限根目录句柄拒绝越界及符号链接，并比较扫描时文件身份、大小和修改时间。已修改或替换的文件必须重新检查后再操作。

响应 `data.files` 返回每个文件的 `cloud_path_id`、`path`、`status`（`deleted`、`missing`、`failed`）及可选 `error`。`data.emby_refresh` 返回 `status`（`requested`、`failed`、`skipped`）与说明。`data.status` 为更新后的扫描状态，契约同 `GET /api/emby-version-check/status`。

请求取消或断线时已经处理的文件仍会从服务端快照移除；客户端应重新读取状态，不能盲目复用旧选区重试。服务重启后内存扫描任务失效，需重新扫描。

## 验证边界

删除和 Emby 刷新测试使用临时目录、临时 SQLite 与模拟 Emby。覆盖文件身份变化、账号/映射失效、越界、符号链接、部分失败、旧任务、并发任务互斥和 Emby 通知失败；浏览器只验证详情、确认与取消。未使用真实媒体执行删除或验证 Emby 扫描完成。

# 媒体目录与旧版本升级

媒体目录统一管理 STRM 同步和媒体整理。`model.MediaDirectory` / `media_directories` 是唯一配置来源，公共 STRM 保存路径、播放前缀和 URI 编码只存一份；同步与整理各自的过滤规则具有不同含义，分别保存。

## 使用方式

新版入口为 `/media-directories`。用途不再由开关控制，保存时按去除首尾空白后的关键配置自动启用，至少完成一项：

- STRM 同步：填写源路径启用，并校验 CloudDrive2 / MoviePilot2 事件来源、STRM 类型和同步文件规则；源路径留空则不参与同步。
- 媒体整理：填写云端目录 ID 启用（`0` 也是有效的非空配置），保留识别引擎、分类、整理过滤和洗版规则；目录 ID 留空则不作为整理目标。

两项都填写时同时启用；仅填写一项时不要求补齐另一项的专属字段。已填写的洗版策略仍检查规则组引用，避免无效或跨账号引用。清空源路径或目录 ID 会停用对应用途，存在任务或配置引用时仍拒绝清空。保存配置不会立即整理文件或生成 STRM，后端查询和执行入口继续按已保存的用途筛选。

已有数据不会在读取或启动时被批量改写；下次保存（含增量编辑）时按合并后的完整配置重新计算用途。历史记录中已填写但曾手动关闭的用途也遵循此规则。

旧版菜单合并为“媒体目录”，旧配置页面跳转到新版编辑器；新版的 `/directories` 和 `/cloud-paths` 收藏地址仍打开同一页面。整理详情的旧 URL 和目录 ID 保留。

## STRM 保存目录选择

新版的 STRM 保存路径支持手动输入，也可从同一行的树形下拉选择服务器目录，选择后回填完整路径。树展示 FilmFusion 进程可见的目录；Docker 部署只能选择容器内可见的路径，宿主目录需要先挂载。

`GET /api/local-directories` 只供已登录的后台管理员使用，不分配 API Token scope。省略 `path` 返回文件系统根节点（Windows 为可访问盘符），传入绝对目录路径时仅返回直属子目录；`page` 从 1 开始，`page_size` 默认 50、最大 200，返回 `items[{name,path}]`、`page`、`total` 和 `has_more`。响应禁止缓存，符号链接仅在指向可访问目录时展示。接口不递归扫描、不读取文件内容、不创建目录或写入 STRM；不存在或无权读取的分支返回相应错误，手动输入尚未创建的保存路径仍沿用原有保存行为。

## 自动迁移

迁移实现全部位于 `app/database/migrations/`，在服务及后台任务启动前执行。

1. 查询 `schema_migrations` 的 `merge_media_directories_v1` 完成记录。
2. 有旧表时，使用 SQLite `VACUUM INTO` 在数据目录的 `backups/before-media-directories-*.db` 创建一致性备份，文件权限为 `0600`。
3. 在同一写事务中创建新结构、复制全部记录（含软删除记录）、转换关联和任务快照，核对记录数，然后删除两张旧配置表并写入完成记录。
4. 失败则回滚本次数据转换，阻止服务启动，不留下部分成功的关联。排除失败原因后重新启动即可重试。

原整理目录保留 ID；原映射 ID 加上原整理目录的最大 ID，以避免两个旧 ID 空间碰撞。PlutoFish 配置、Emby 定时多版本检查和整理日志同步转换映射引用。自动化、整理预览、洗版记录的整理目录 ID 不变。

旧整理计划的配置快照与洗版恢复任务的目录快照只转换结构，不以当前配置覆盖历史快照。原有“配置已改变”的检查仍然有效。历史日志中已无对应配置的 ID 会保留独立编号，并推进新目录序列，避免将历史日志错误关联到未来新建的目录。

迁移逐条保留配置，不根据名称或文本路径自动去重。云端目录 ID、CloudDrive2 挂载别名和过滤规则无法离线证明等价，自动去重可能改变既有输出。旧映射只启用映射，旧整理目录只启用整理。

当前业务字段保留原始数据库值，包括 `NULL`、JSON 文本及时间戳。已在旧版本移除执行逻辑的 `is_windows_path` 只留在完整备份中，不重新引入业务表；其他未知列会阻止迁移，避免静默丢失数据。

全新安装直接创建新结构和完成记录。迁移后再次启动不会重复转换或重复备份，也不会恢复旧表。若完成迁移后检测到旧表重新出现，则停止启动，防止新旧程序混用数据库。

## API 与权限

统一配置 API：`/api/media-directories/`，支持 GET、POST，以及 `/:id` 的 GET、PUT、DELETE。列表可用 `capability=mapping` 或 `capability=organize` 筛选。PUT 是增量更新：未提交字段保留原值，显式空字符串清空可选文本；拒绝修改 ID、所有者等内部字段。

`mapping_enabled` 与 `organize_enabled` 是服务端推导并保存的结果，仍在响应中返回，供筛选与执行入口使用。新前端不提交这两个字段；旧客户端传入布尔值时允许解析，但不能覆盖根据源路径、目录 ID 得出的结果。只有默认来源、公共保存路径或播放前缀，而没有任何源路径或目录 ID 时，返回配置校验错误。

浏览器、STRM 任务和内容替换操作位于该资源下。API Token 使用独立的 `media-directories` 权限，不自动扩大旧 Token 的权限。

已发布浏览器扩展所需的 `GET /api/directories/` 保留为只读整理目录视图，复用统一查询及原 `directories` 权限；没有旧表或第二套保存逻辑。旧 `/api/paths/*` 和旧目录写接口不再提供，外部自编脚本需要改用新 API 并明确授权新权限。当前管理前端已同步更新调用。

现有自动化、PlutoFish 等协议中的 `cloud_directory_id` / `cloudPathID` / `cloud_path_ids` 字段名保留，数值均引用统一媒体目录，不建立第二套数据模型。

删除、停用用途或切换网盘账号前会检查显式配置关联和整理恢复任务；存在引用时返回冲突，不静默丢弃关联。

## 发布与回退

发布前执行后端测试，并通过 `build-frontends.sh` 构建唯一的新版前端。停止所有旧版本进程后再启动新版，禁止多个版本同时使用同一数据库。

回退需要先停止新版，用升级前的完整数据库备份恢复原数据库，再启动对应旧程序；不要直接让旧程序打开已经迁移的新数据库。备份可能包含账号凭据，按原数据库的私有数据管理。

验证覆盖迁移幂等、ID 冲突、软删除保留、关联转换、失败回滚、原始字段值、快照兼容、用途隔离、增量更新和所有者隔离。云端文件整理、真实洗版及播放验收应使用独立测试媒体，数据库升级本身不触发这些操作。
